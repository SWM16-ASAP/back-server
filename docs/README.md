# Project Documentation

## 목적

이 문서는 이 프로젝트를 아래 두 관점에서 통제하기 위한 기본 문서다.

- 리팩터링과 성능 개선을 위한 현재 구조 이해
- 구조적 문제, 기술적 선택, 개선 의사결정 과정을 기록하기 위한 기준 정리

이 문서는 사람이 읽는 개요 문서이면서, LLM이 현재 프로젝트 구조와 문서화 범위를 빠르게 파악하기 위한 기준점으로도 사용한다.

## 문서화 원칙

- 문서는 UML 자체가 목적이 아니라 구조를 통제하기 위한 지도여야 한다.
- 프로젝트 개요는 루트 `README.md`에 두고, 이 문서는 구조와 개선 방향에 집중한다.
- 클래스 전체를 나열하기보다 도메인, 책임 경계, 대표 흐름을 우선 문서화한다.
- 문서 수를 과하게 늘리지 않고 핵심 구조와 의사결정 기록 중심으로 유지한다.
- 개선 전후 차이를 설명할 수 없는 문서는 우선순위를 낮춘다.
- 모든 결정을 다 기록하지 않고, 구조, 성능, 안정성, 테스트 전략에 영향을 주는 큰 의사결정만 기록한다.

## 현재 프로젝트 개요

### 애플리케이션 성격

- Spring Boot 기반 API 서버
- 주 데이터 저장소는 MongoDB
- Redis를 캐시 및 rate limiting에 사용
- S3 / R2 계열 스토리지, Firebase, Sentry, 모니터링 도구가 함께 연결된 운영형 백엔드

### 주요 구성 요소

- `auth`: 인증, JWT, 보안 필터
- `content`: 기사, 책, 커스텀 콘텐츠, 피드, 추천
- `streak`: 학습 연속성, 보상, 스케줄러, 회복 로직
- `word`: 단어 조회, 검증, 변형, AI 연계
- `common`: 공통 설정, 예외 처리, rate limit, 유틸리티
- `s3`: 파일 경로 전략, 업로드/다운로드, 이미지 처리
- `fcm`: 알림 및 토큰 관리

### 운영 및 인프라

- MongoDB
- Redis
- S3 / R2
- Firebase
- Sentry
- Spring Actuator
- Prometheus / Grafana
- Loki / Promtail
- GitHub Actions
- k6 성능 테스트 자산

## 핵심 문서화 대상

이 프로젝트에서 먼저 문서화하고 관리할 영역은 아래와 같다.

1. `streak`
2. `word`
3. `content/book`
4. `common/ratelimit`

이 영역들은 비즈니스 복잡도, 성능 최적화 포인트, 운영성, 의사결정 기록 가치가 모두 높다.

## 후순위 문서화 대상

아래 영역은 외부 환경 변수의 영향을 크게 받아 초반 핵심 문서화 대상에서는 제외한다.

1. `content/feed`
2. `crawling`
3. 외부 네트워크 의존 통합 흐름

이 영역은 추후 안정성 개선과 외부 의존성 관리 사례로 분리해 다룬다.

## 대표적으로 정리할 구조와 흐름

현재 단계에서 먼저 정리할 구조와 흐름은 아래와 같다.

1. 시스템 컨텍스트와 주요 외부 시스템 연결
2. 애플리케이션 도메인 맵
3. `streak` 갱신 및 보상 처리 흐름
4. `content/book` 조회와 진행도 계산 흐름
5. `word` 조회/분석 흐름
6. `common/ratelimit` 요청 차단 흐름

## 개선 방향

이 프로젝트는 아래 방향으로 개선한다.

1. 테스트를 안정화하고 외부 의존 테스트를 분리한다.
2. 큰 서비스를 작은 단계로 리팩터링한다.
3. 클린코드를 위한 구조 개선을 반복한다.
4. 측정 가능한 근거를 기반으로 성능을 개선한다.
5. 높은 트래픽을 가정한 안정성을 개선한다.

## 의사결정 기록 기준

큰 의사결정은 아래 다섯 항목만 기준으로 간단하게 정리한다.

- 문제: 현재 어떤 구조적/성능/안정성 문제가 있는가
- 선택: 어떤 방향을 택할 것인가
- 이유: 왜 이 선택이 더 적절한가
- 검증: 무엇으로 개선 여부를 확인할 것인가
- 남은 이슈: 아직 남은 리스크나 다음 단계는 무엇인가
